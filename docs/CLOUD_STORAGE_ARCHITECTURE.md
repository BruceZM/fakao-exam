# 法考项目中国大陆云端存储架构建议

## 推荐结论

第一阶段建议使用同一国内云厂商的三个核心服务：

- **COS 对象存储**：保存原始 PDF/DOCX、OCR 文本、扫描报告、导入快照和备份包。
- **托管 PostgreSQL**：保存题目、选项、答案、解析、知识点、法条、评分点、来源、授权状态、审校记录和用户学习数据。
- **Redis**：保存登录会话、限流、短期缓存和组卷任务状态，不作为唯一数据源。

当前项目的 SQLite 快照继续作为本地开发和离线审校格式；云端产品数据库从 SQLite 导入经过审核的结构化数据，不建议让线上服务直接读写本地 SQLite 文件。

## 地域与网络

生产资源选择中国大陆单一主地域，例如上海或广州；对象存储、数据库、应用服务尽量同地域，通过私有网络访问。备份放到另一个中国大陆地域，避免把生产数据默认复制到中国香港或境外。

原始资料桶必须私有，前端只通过后端签发的短时授权 URL 下载经过准入的文件。题目接口只返回已经通过产品准入的数据，不返回原始 OCR 或未授权资料。

## 数据分层

| 层 | 内容 | 推荐存储 | 访问边界 |
|---|---|---|---|
| 原始资料层 | PDF、DOCX、OCR、扫描报告、哈希 | COS 私有桶 | 仅管理员/审校人员 |
| 研究审校层 | 1117 道题、答案、解析、候选法条、审校队列 | PostgreSQL | 管理后台和内部服务 |
| 产品内容层 | 已授权、已复核、已确定法律版本的题目和解析 | PostgreSQL 只读 schema/视图 | 用户端 API |
| 用户数据层 | 账号、练习记录、错题、收藏、订阅、反馈 | PostgreSQL 独立 schema | 用户本人和受限后台 |
| 缓存层 | 会话、限流、热门题目、异步任务 | Redis | 服务内部 |
| 搜索层 | 题干、解析、知识点和资料检索索引 | PostgreSQL FTS；规模变大后再加 OpenSearch/向量库 | 后端查询服务 |

## 当前 SQLite 的迁移方式

1. 保留 `data/fakao_knowledge_base.sqlite` 作为版本化离线快照和审校基线。
2. 将 `sources`、`materials`、`reference_documents`、`questions`、`options`、知识点和法条关联映射到 PostgreSQL。
3. 产品 API 只读取 `product_admission = admitted` 的视图；`needs_human_review`、`blocked` 和授权 unknown 的内容留在研究审校层。
4. 用户答题记录与题库内容使用不同 schema，并通过稳定 `question_id` 关联。
5. 每次发布生成快照版本、迁移日志和可回滚备份，禁止在线直接改原始导入文件。

## 安全与合规基线

- 数据库和对象存储开启静态加密；传输只允许 HTTPS/TLS。
- 管理员启用 MFA，按“管理员、审校员、运营、用户”分角色授权；原始资料和授权凭证使用最小权限。
- 开启对象版本控制、数据库自动备份、异地备份和恢复演练；备份保留周期单独配置。
- 记录管理员查看、导出、修改和删除日志；用户学习记录支持查询、更正、删除和注销。
- 账户、手机号、支付和学习行为属于用户数据，和题库原始资料分开存储；不把手机号、邮箱写入题目文本或日志。
- 在隐私政策中说明收集目的、范围、保存期限、第三方云服务、用户权利和客服渠道；只收集完成学习功能所必需的信息。
- 上线前核对 ICP 备案、网络安全等级保护定级/备案、域名、隐私政策和内容授权；云厂商地域选择本身不等于完成合规。

## 分阶段落地

### 内部 alpha

使用一台国内云应用服务、COS 私有桶、托管 PostgreSQL 和 Redis。只开放已授权或自有原创的少量示例题，研究资料继续只供管理员和审校员使用。

### 公测

增加 CDN/WAF、数据库高可用、异地备份、审计日志、账号注销和数据导出；完成题库来源授权和产品准入规则后再扩大内容范围。

### 正式商业版本

完成来源授权、法律专家复核、法条版本管理、主观题评分规则审校、恢复演练和合规备案。产品数据库与研究资料库保持逻辑隔离，发布通过版本化导入完成。

## 与教资项目方案的关系

教资项目当前采用题库 JSON 随 Docker 镜像发布、服务无状态、仅将访客统计 SQLite 持久化到 `/mnt/workspace` 的方式。这个方案部署简单、题库读取快，也适合先做法考内部 alpha。

法考项目可以复用教资项目的部署脚本、环境变量管理、健康检查和“持久化目录不放密钥”的做法，但不应原样复用数据层：法考当前有 1117 道题、38 份 OCR 参考资料、审校队列、来源授权状态和后续用户学习记录，全部打包进镜像会导致更新、回滚、权限隔离和用户数据同步变得困难。

建议按阶段处理：

- **内部 alpha**：暂时把已经准入的少量产品 JSON 随镜像发布，COS 只保存原始资料和备份，继续保持无状态。
- **公测**：题库迁移到托管 PostgreSQL；用户进度、错题、收藏和订阅单独存储；COS 保存版本化导入包。
- **正式版本**：研究审校库、产品库和用户数据分层，发布通过版本化迁移完成；容器重启不影响业务数据。

因此，教资方案适合作为法考的部署起点，不适合作为法考最终的数据架构。

## 选择厂商

腾讯云的 COS 文档明确提供中国大陆地域并建议按业务位置选择地域，以兼顾延迟、成本和合规；腾讯云 PostgreSQL 提供托管实例、备份、恢复和高可用能力。阿里云的 OSS + RDS PostgreSQL 也可以采用同样架构。建议先选一家，避免跨厂商网络、权限和备份复杂度。
